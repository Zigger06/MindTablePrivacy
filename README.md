# MindTable Privacy

Публичный сайт политики конфиденциальности MindTable, готовый для GitHub Pages. Статический HTML: доступен без авторизации, JavaScript и внешних сервисов рендеринга. Текст политики уже находится в каждой HTML-странице.

## Публикация

В этом репозитории откройте **Settings → Pages**:

1. **Source:** `Deploy from a branch`.
2. **Branch:** `main`.
3. **Folder:** `/(root)`.
4. Нажмите **Save**. После завершения публикации откройте адрес, показанный GitHub.

| Язык | Планируемый публичный адрес |
| --- | --- |
| Русский | https://zigger06.github.io/MindTablePrivacy/ |
| English | https://zigger06.github.io/MindTablePrivacy/en/ |
| Тоҷикӣ | https://zigger06.github.io/MindTablePrivacy/tg/ |

Это адреса после включения Pages, а не подтверждение того, что сайт уже опубликован. Включение Pages оставлено владельцу репозитория.

Один публичный адрес политики можно использовать в Google Play, в настройках сообщений AdMob и в `privacy_policy_url` игры. Для международной страницы магазина подойдёт английская версия. Убедитесь, что страница действительно открывается без входа, прежде чем добавлять ссылку в релиз.

## Содержание и контакт

Политика подготовлена по реализации MindTable в коммите [`82f78d5`](https://github.com/Zigger06/MindTable/commit/82f78d52a35d1be6d8a29a745658decbaf8fe582), а не по шаблонному утверждению «мы не собираем данные».

Она охватывает локальные настройки и незавершённые партии, ограничения рекламы, Google AdMob / UMP, прямой обмен по Wi‑Fi и Bluetooth, Android-разрешения, сроки хранения, удаление, рекламный выбор, несовершеннолетних, безопасность, размещение на GitHub и контактный механизм.

Пока контакт ведёт в **GitHub Issues**. Это работающий публичный механизм обращения, но для частных запросов удобнее отдельный email разработчика. Email не придуман и не взят из истории Git-коммитов. Если добавите адрес, обновите контактные разделы во всех языках. На сайте прямо указано, что публичные обращения не должны содержать персональные сведения.

Разработчик указан как **Zigger06**, MindTable явно назван в политике. Если в магазине будет другое публичное название разработчика или юридическое лицо, приведите сведения в политике к тому же виду.

## Редактирование

- `content/policy.json` — единый источник текста на трёх языках; `body` содержит доверенный HTML, редактируемый владельцем.
- `scripts/build.py` — генератор на стандартной библиотеке Python 3.12+.
- `index.html`, `en/index.html`, `tg/index.html` — готовые страницы для Pages; никакая серверная сборка не нужна.
- `assets/style.css` — оформление, мобильная адаптация и печать.
- `assets/site.js` — только печать и подсветка текущего раздела; не собирает информацию и не записывает cookies или localStorage.

После изменения текста выполните:

```bash
python scripts/build.py
```

Добавьте в коммит источник и сгенерированные HTML-страницы. При существенном изменении практик обновите дату и редакцию в JSON, шаблоне и `sitemap.xml`, а также соответствующие настройки игры и магазина. Изменение политики само по себе не добавляет отсутствующих механизмов согласия или защиты в игру.

Для просмотра локально:

```bash
python -m http.server 8000
```

Затем откройте `http://localhost:8000/`. Текст и ссылки работают без JavaScript. Страница пригодна для печати из браузера. Внешние шрифты, трекеры, рекламные скрипты и формы на сайт не добавлены.

## Важно для app-ads.txt

В репозитории подготовлен `app-ads.txt` с издателем `pub-7981531829739126`. Перед публикацией сравните строку с персональным фрагментом **AdMob → Apps → View all apps → app-ads.txt → How to set up app-ads.txt**; при необходимости используйте точную строку из аккаунта.

**Политика по адресу `/MindTablePrivacy/` и проверка app-ads.txt — разные задачи.** AdMob ищет файл в корне домена сайта разработчика:

```text
https://zigger06.github.io/app-ads.txt
```

Файл по адресу `https://zigger06.github.io/MindTablePrivacy/app-ads.txt` сам по себе не решает эту проверку. Для домена `zigger06.github.io` разместите файл в корне отдельного репозитория **`Zigger06/Zigger06.github.io`**, либо подключите к этому сайту собственный домен, на котором файл будет доступен как `/app-ads.txt`. Автоматический сборщик AdMob ориентируется на сайт разработчика, указанный в карточке магазина.

Политика полностью пригодна для публикации в этом project-repository; менять название репозитория ради неё не нужно.

## Перед экспортом релиза

1. Опубликуйте Pages и проверьте прямой HTTPS-адрес.
2. Добавьте этот адрес в настройки игры, Google Play и сообщения AdMob.
3. Создайте и опубликуйте применимые сообщения согласия в **Privacy & messaging**. UMP интегрирован в игру, но текст политики не заменяет настройку сообщения в AdMob.
4. Проверьте возрастную аудиторию в Google Play и соответствующие параметры рекламы. Сайт не заявляет соответствие Families/COPPA и не объявляет выдуманное возрастное ограничение; одной политики недостаточно для настройки рекламы детям.
5. Заполните **Data safety** с учётом данных Google Mobile Ads SDK, а не только локального игрового кода. Сопоставьте сведения с фактическим SDK и конечной release-сборкой.
6. Включайте реальные показы в игре после завершения конфигурации; текущий проект сохраняет тестовые показы.
